# The omcp Manifesto

## 1. Protocols Belong to the Community, Not Gatekeepers

The Model Context Protocol was open-sourced under permissive licensing to ensure that AI
context integration would be an open, interoperable standard. Open standards exist so that
no single entity or central committee holds the keys to innovation. When maintainers restrict
development behind discretionary social filters and unchartered real-time chats, they abandon
the spirit of permissionless open source.

## 2. Code Over Closed-Door Bureaucracy

An open protocol must be governed asynchronously, transparently, and on the merit of technical
execution. Requiring contributors to seek pre-approval from non-existent or disorganised
working groups—while closing pull requests without technical review—is not governance; it is
passive rejection. omcp rejects real-time gatekeeping, arbitrary bot-detection paranoia, and
bureaucratic friction. If an idea works and improves the spec, it belongs in the open.

## 3. Permissionless Progress

You do not need permission to build, extend, or improve software. omcp was born to restore the
original promise of open source: ship working code first.

**Drop-in Compatibility:** We maintain total interoperability with the broader ecosystem,
including integration with tools like enclawed.

**Transparent Review:** Proposals, RFCs, and pull requests are evaluated openly on GitHub based
on technical merit and utility—never on Discord vibe checks.

**Driven by Adoption:** Standards are defined by what developers actually use in production,
not by corporate steering committees.

## 4. Nobody Cares How You Built It

Nobody cares how an idea has been implemented, for as long as it is good code that works and
solves a real problem.

The tools you reached for are your business. There is nothing to disclose, nothing to justify,
and no declaration to file. A good idea is a good idea regardless of what executed it, and code
is judged on what it does — not on the process that produced it, the pedigree of its author, or
the fashions of the moment.

Authorship belongs to humans. The person who opens the pull request is its author, is accountable
for it, and is credited for it. Accountability is the part that matters, and it does not change:
you understand the change, you can state the problem it solves, and you have shipped tests that
anybody can run to prove it.

Judge the diff. Nothing else was ever the point.

---

omcp is the community-driven, frictionless evolution of the protocol. **Build without permission.**
